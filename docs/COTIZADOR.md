# KODEXA — Cotizador comercial definitivo

## 1. Propósito y criterio comercial

El cotizador entrega una **estimación preliminar orientativa** para proyectos digitales. Su objetivo es ordenar el alcance, detectar complejidad y generar una solicitud comercial completa; no reemplaza el relevamiento ni constituye una oferta contractual.

Todos los importes están expresados en pesos argentinos (ARS). Los valores del catálogo son parámetros comerciales de referencia y deben revisarse periódicamente por inflación, alcance, costos de terceros, impuestos y capacidad operativa.

## 3. Funciones incluidas en cada producto

La selección de una función incluida no genera un segundo cargo. El motor separa funciones incluidas y módulos adicionales.

| Producto | Incluido en el alcance base |
|---|---|
| Landing page | Estructura de una página, diseño responsive y CTA/formulario de contacto básico |
| Institucional | Sitio multipágina, navegación, contenidos provistos, diseño responsive y formulario básico |
| E-commerce | Catálogo, carrito, checkout y administración básica de productos/pedidos |
| PWA | Aplicación web instalable, responsive y configuración PWA; sincronización offline avanzada no incluida |
| Android híbrida | Base web empaquetada con Capacitor para Android; Web + Android no se cobra como dos productos |
| Android nativa | Aplicación Android específica; iOS no está incluido |
| SaaS multiempresa | Base multi-tenant, autenticación, roles/permisos y panel administrativo inicial |
| Sistema operativo | Autenticación, roles/permisos y panel administrativo inicial para una organización |
| Integración / automatización | Relevamiento acotado y una integración/proceso definido; cantidad y complejidad se validan |
| Producto a definir | Se estima luego del descubrimiento funcional y técnico |

Los alcances base son límites de referencia, no una promesa de funcionalidades ilimitadas. Volumen de pantallas, flujos, perfiles, reglas, migraciones, integraciones y pruebas se define en el relevamiento.

**Reglas de no duplicación:**
- SaaS: autenticación, roles, multi-tenant y panel inicial están incluidos.
- Sistema operativo: autenticación, roles y panel inicial están incluidos; al seleccionar más de una organización, el módulo multi-tenant se agrega automáticamente al cálculo.
- E-commerce: administración básica de catálogo y pedidos está incluida; pasarela de pago, facturación y automatizaciones complejas se cotizan como ampliaciones.
- PWA: instalabilidad no equivale a sincronización offline completa.
- APK híbrida: Web + Android forma parte de la misma solución base.
- Los módulos adicionales pueden requerir servicios, licencias o infraestructura de terceros.

## 5. Ajustes de complejidad

El cotizador aplica factores solamente donde la variable representa esfuerzo técnico:

- **Organizaciones:** se aplica a SaaS y sistemas operativos, con referencias de 1,00 / 1,08 / 1,18 / 1,32. En sistemas operativos o productos a definir, seleccionar más de una organización incorpora automáticamente el módulo multi-tenant; en SaaS ya está incluido en la base.
- **Usuarios:** se aplica a aplicaciones y plataformas (PWA, híbrida, nativa, SaaS, sistemas y producto a definir), con referencias de 1,00 / 1,08 / 1,20 / 1,38.
- Landing, institucional y e-commerce no reciben un recargo automático por cantidad de usuarios: el tráfico y el consumo se evalúan en infraestructura.
- Las plataformas seleccionadas se informan en el pedido, pero no se multiplican por un porcentaje arbitrario.
- iOS requiere evaluación y cotización específica. No se presume que una app Android se convierta automáticamente en una app iOS.

Los factores son bandas comerciales orientativas, no una medición exacta de horas. El alcance final prevalece sobre el multiplicador.

## 6. Mantenimiento y continuidad

El cotizador muestra dos referencias sobre la inversión inicial estimada:

- **Esencial — 8% mensual:** referencia para mantenimiento correctivo, actualizaciones y ajustes menores.
- **Continuo — 12% mensual:** referencia para soporte y evolución planificada.

Estos porcentajes no constituyen un SLA ni compran horas ilimitadas. La propuesta formal debe especificar horas incluidas, canales de soporte, horarios, tiempos de respuesta, backups, monitoreo, actualizaciones y exclusiones. Nuevas funcionalidades, cambios de alcance y desarrollos evolutivos mayores se estiman por separado.

## 7. Infraestructura y costos de terceros

No están incluidos en el precio de desarrollo ni en el porcentaje de mantenimiento, salvo que una propuesta lo indique expresamente:

- Hosting, servidores, base de datos y ambientes.
- Almacenamiento, transferencia y tráfico.
- Servicios de correo, SMS, WhatsApp y push.
- Mapas, geolocalización y proveedores de datos.
- TURN/WebRTC, voz, grabaciones y retención.
- Pasarelas de pago, comisiones y facturación.
- Licencias, dominios, certificados y cuentas de tiendas.
- Consumo de IA y APIs de terceros.

Se dimensionan según volumen, proveedor y condiciones vigentes.

## 8. Flujo de solicitud y privacidad

1. La persona selecciona producto, arquitectura y módulos.
2. El cálculo se realiza localmente en el navegador.
3. Completa nombre y teléfono; empresa, email y descripción son opcionales.
4. Se prepara un mensaje con el resumen para WhatsApp comercial: **5492213642475**.
5. La persona revisa y decide enviarlo desde WhatsApp.

No se utiliza backend, CRM, Supabase ni almacenamiento local para persistir los datos del formulario. El navegador abre WhatsApp con el texto preparado; el usuario debe confirmar el envío.

## 9. Límites técnicos y comerciales

- PWA, APK híbrida y Android nativa son productos diferentes.
- Capacitor empaqueta una aplicación web y permite integrar funciones del dispositivo; no equivale a desarrollo Android nativo.
- Push-to-Talk requiere dimensionar concurrencia, latencia, cobertura, TURN, seguridad, grabación y retención.
- Integraciones con ARCA, pagos, WhatsApp, Apple/Google y otros proveedores dependen de credenciales, aprobaciones y políticas externas.
- Migraciones, importación/limpieza de datos, auditorías, certificaciones, pentesting y alta disponibilidad se cotizan según alcance.
- La estimación no incluye impuestos ni costos de terceros salvo indicación expresa en la propuesta.

## 10. Control de calidad antes de publicar

- Navegación completa de las cuatro etapas.
- Validación de campos obligatorios y accesibilidad básica.
- Cambio entre productos y actualización de módulos incluidos.
- Confirmación de que los módulos incluidos no se suman al precio.
- Pruebas de factores por tipo de producto, organizaciones y usuarios.
- Verificación de APK híbrida sin recargo artificial por Web + Android.
- Revisión del resumen y mensaje de WhatsApp.
- Pruebas responsive en escritorio y móvil.
- Confirmación del workflow de GitHub Pages y comprobación del sitio publicado.

## 11. Estado de los valores

Los valores actuales son una **matriz comercial de referencia**, no tarifas estadísticamente validadas ni un compromiso contractual. Antes de aceptar un proyecto, KODEXA debe convertir la estimación en alcance cerrado, hitos, entregables, cronograma, condiciones de pago, garantía, soporte y costos externos.
